# StoreLens — прежде чем платить

Рабочий прототип веб-сервиса проверки интернет-магазинов. Введите ссылку: сервер независимо проверит доступные страницы, историю домена и веб-архив, затем составит отчёт с источниками. Отказ магазина в доступе не отменяет остальные проверки.

**Это ещё не полноценный аналог Fraudly.** Поиск внешних ссылок реализован через Brave Search API, но требует собственного ключа. ИИ, проверка реестров организаций, подтверждение репутации и базы угроз не реализованы. Прототип не выносит положительный вердикт о надёжности: наличие HTTPS, телефона или ИНН не доказывает честность продавца.

## Запуск на своём компьютере

Нужен Python **3.11 или новее**. Для базового режима платные API и установка библиотек не нужны. Проект можно скачать через **Code → Download ZIP** или клонировать с помощью Git:

```bash
git clone https://github.com/YourSam/CODEX.git
cd CODEX
python3 app.py
```

На Windows вместо `python3 app.py` используйте `py -3 app.py`.

Откройте в браузере `http://127.0.0.1:8000`. Остановка — Ctrl+C. Если порт занят: `python3 app.py --port 8001`.

### Рекомендуемый запуск на Mac с браузером

Остановите предыдущий сервер через Control+C. В копии, скачанной через Git:

```bash
cd ~/StoreLens
git pull --ff-only
bash ./start-mac.command
```

Откройте `http://127.0.0.1:8001`. Скрипт переходит в свою папку, создаёт в ней отдельную `.venv-browser`, устанавливает зависимости и Chromium, затем проверяет реальный запуск браузера до старта сервера. Старая активированная среда из папки ZIP не используется. При ошибке установки сервер не запускается. Последующие запуски — той же командой; уже установленные зависимости и браузер используются повторно.

Рядом с логотипом показывается **«Chromium проверен»**, только если браузер действительно запускался. Для отдельной проверки: `.venv-browser/bin/python app.py --check-browser`. Обычный HTML-режим остаётся доступен через `python3 app.py`.

Если репозиторий уже скачан, выполните `git pull --ff-only` из его папки перед запуском. Если вы на другой ветке, переключитесь на ветку с прототипом, указанную в GitHub. Не перезаписывайте свои локальные изменения.

GitHub хранит исходники; публичный сайт автоматически не создаётся. В облачной onboarding-среде нет пользовательского веб-превью. Для тестирования интерфейса используйте локальный запуск; публичный хостинг подключается отдельно.

## Что тестировать

Текущая версия — **0.5.1**: она видна рядом с логотипом и в консоли при запуске. Проверка установленной копии: `python3 app.py --version`. Если вы скачивали ZIP, повторное скачивание не обновляет уже работающий сервер: остановите старый процесс и запустите `app.py` из новой распакованной папки. Чтобы не перепутать с другой работающей копией, можно запустить новую с `--port 8001` и открыть порт 8001 в браузере.

При неудачной загрузке верхний блок показывает обычный загрузчик и Chromium отдельно. Возможны повторный HTTP-отказ браузеру, сетевая / TLS-ошибка с кодом Chromium или явное сообщение, что попытка не выполнялась из-за авторизации. «Chromium проверен» в шапке подтверждает только запуск программы. Текст исключения браузера не публикуется целиком: в отчёт попадают лишь код `ERR_*` и безопасное объяснение без исходных URL с параметрами и заголовков.

1. Вставьте `galaxyshub.ru`, `galaxypoint.ru`, `kadrum.store`, `fmart.com.ru` или `tecnotop.ru` либо нажмите соответствующий пример. Никаких заранее подготовленных оценок для этих магазинов нет.
2. Дождитесь отчёта. Проверьте найденные фрагменты по ссылкам на источники. Обработка обычно занимает до минуты, но зависит от сети и источников.
3. Попробуйте несуществующий домен: недоступность должна давать недостаток данных, а не обвинение в мошенничестве.
4. Попробуйте Instagram-профиль: получите явное сообщение, что анализ профиля не подключён, и предложение проверить сайт из его описания. Мы не выдаём репутацию платформы за репутацию продавца.
5. Ссылка `http://127.0.0.1` должна быть отклонена; локальные и служебные сети недоступны загрузчику.
6. Кнопка «Сохранить PDF» открывает печать браузера: выберите сохранение в PDF.
7. Если магазин возвращает 401 / 403 / 429, причина сразу видна в верхнем блоке. История домена, архив и настроенный поиск проверяются независимо; при наличии результатов появляется частичный отчёт. Это не гарантирует получение данных из внешних источников.

## Источники и настройка

| Источник | Настройка | Что подтверждает |
| --- | --- | --- |
| HTML магазина | Работает по умолчанию | Что написано на доступных страницах |
| RDAP | Без ключа, нужен доступ к `rdap.org` и серверу соответствующей зоны | Дата регистрации, если опубликована |
| WHOIS .ru / .рф | Резерв после отказа RDAP; нужен прямой TCP 43 к `whois.tcinet.ru` | Дата `created` для домена второго уровня; не личность продавца |
| Internet Archive CDX | Без ключа, нужен доступ к `web.archive.org` | Метаданные сохранённой главной страницы, не её текущее содержимое |
| Brave Search | Собственный ключ и доступ к `api.search.brave.com` | Внешние ссылки и поисковые фрагменты; не достоверность отзывов |
| Chromium / Playwright | Необязательная установка ниже | Текст после JavaScript для уже доступной HTML-страницы |

RDAP, WHOIS и веб-архив могут быть недоступны или ограничивать частоту запросов. WHOIS-резерв поддерживает только домены второго уровня .ru / .рф, проверяет совпадение имени в ответе, не следует переадресациям и не используется при настроенном HTTP-прокси. Доступ к TCP не предполагается и не обходится. Для .com.ru и других составных / неподдерживаемых зон остаётся RDAP. Источник WHOIS в отчёте обозначен явно; ссылка IANA описывает сервер зоны, а не служит копией WHOIS-ответа.

### Браузерная загрузка на Mac

Из папки проекта выполните:

```bash
python3 -m venv .venv-browser
source .venv-browser/bin/activate
python -m pip install -r requirements-browser.txt
python -m playwright install chromium
python app.py --browser --port 8001
```

После повторного открытия Терминала достаточно активировать `.venv-browser` и выполнить последнюю команду. Обычный режим продолжает работать без Playwright.

Браузер используется для динамического HTML и для одной анонимной попытки загрузки публичной страницы после HTTP 401 **без заголовка WWW-Authenticate**. Явный запрос авторизации, HTTP 403, CAPTCHA и повторные отказы сохраняются как ограничения. Браузер не получает ваши Safari-куки, не авторизуется и не решает CAPTCHA; использует только cookies своей новой сессии. Данные API, требующих POST или авторизации, могут остаться недоступны. Установка браузера **не гарантирует доступ к DNS Shop**.

С версии 0.5.0 Chromium действительно выполняет сетевые запросы сам: они больше не подменяются ответами Python-загрузчика. Браузер работает в отдельном процессе с sandbox и временным loopback-прокси. Прокси проверяет домен и порт каждого соединения, запрещает частные адреса, закрепляет публичный IP при прямом соединении и сохраняет настроенный платформенный прокси. При его отказе прямого обходного соединения нет. TLS проходит между Chromium и сайтом без подмены сертификата; проверка сертификатов включена. Входящие HTTP-заголовки прокси не принимаются за заголовки сайта.

В браузере разрешены GET, ограничены число запросов и время; WebSocket, WebRTC и фоновые worker-API отключены, service workers блокируются. Изображения, видео и шрифты не загружаются. Навигация основной страницы ограничена исходным хостом и его вариантом с / без www, переход HTTPS → HTTP запрещён. Публичные подресурсы могут загружаться с других доменов. HTTPS-туннель ограничен по объёму и времени, но прокси не инспектирует зашифрованное содержимое; методы ограничиваются маршрутизатором Chromium. Основной процесс останавливает браузер после 25 секунд. На Linux необходимы поддержка sandbox и изоляция исходящего трафика; отключать sandbox для произвольных сайтов нельзя. `STORELENS_BROWSER_EXECUTABLE` позволяет выбрать установленный Chromium без отключения sandbox.

### Внешний поиск на Mac

Получите ключ в [Brave Search API](https://api-dashboard.search.brave.com/) и проверьте текущие тарифы и условия использования. В **том же Терминале**, где будете запускать сервер, выполните:

```bash
read -s STORELENS_SEARCH_KEY
```

Вставьте ключ и нажмите Enter: ввод скрыт. Затем:

```bash
export STORELENS_SEARCH_KEY
python3 app.py --port 8001
```

Для браузерного режима используйте активированную виртуальную среду и `python app.py --browser --port 8001`. Не вводите ключ аргументом команды, в чат или Git. В облачной среде добавляйте его через настройки секретов с назначением `api.search.brave.com`.

Поиск отправляет провайдеру доменное имя, а не полный URL с параметрами. За одну проверку выполняется один поисковый запрос; автоматических повторов после ошибок нет. Ключ не возвращается в отчёт и не переносится при перенаправлении API. Поисковые фрагменты явно помечены как непроверенные: число результатов и упоминания слова «мошенничество» не превращаются в вердикт или положительные баллы.

Статусы: **найдено** — сведения действительно получены, но не обязательно независимо подтверждены; **обратить внимание** — найден конкретный ограниченный сигнал риска; **не удалось подтвердить** — данных нет или источник недоступен; **не подключено** — такая проверка не запускалась.

В начале отчёта есть индивидуальный итог: рекомендация перед оплатой, сведения, на которые он опирается, пробелы проверки и отдельные поводы для осторожности. Каждый пункт ссылается на соответствующую проверку ниже. Недоступный сайт и неподдерживаемый Instagram получают свои рекомендации. Итог составляется по правилам, без ИИ; непроверенные сведения не превращаются в обвинение или гарантию безопасности.

### Оценка из 100

Первым показан блок «Уверенность в сайте» с числом из 100, полнотой полученных данных и коротким выводом. Ниже — три причины со ссылками на проверки; подробный отчёт раскрывается по нажатию. При печати подробности открываются автоматически.

Число — **предварительный индекс найденных подтверждений, не вероятность безопасности и не откалиброванная модель мошенничества**. Методика `evidence-0.1` использует фиксированный знаменатель: HTTPS — 5 баллов, контакты — 5, заявленные реквизиты — 5, текст о возврате — 10, текст об оплате — 10, домен старше 180 дней — 5. Только статус `observed` приносит баллы; предупреждения, неизвестные и неподключённые источники — нет. Отсутствие баллов не считается негативным фактом о продавце.

Ещё 60 баллов зарезервированы за независимыми подтверждениями: реестр — 25, репутация — 25, базы угроз — 10. Эти интеграции пока не реализованы и не начисляют баллов даже при ошибочном изменении статуса заглушки. **Текущий максимум — 40/100**: красивый сайт с заполненными страницами не может получить высокий балл за одну только собственную информацию. Весовая схема пока экспертная, без проверки на размеченной выборке; она требует пересмотра вместе с подключением источников.

Если магазин недоступен, Instagram не поддерживается либо кроме технических сведений ничего не получено, вместо числа показывается **—/100**, а не нулевой рейтинг магазина. При этом внешние результаты сохраняются в частичном отчёте. Архив и поисковые фрагменты не начисляют баллы репутации. Разбивка всех баллов доступна в «Как рассчитаны баллы» со ссылками на проверки.

Текст ссылок, меню, шапки и подвала не считается текстом условий оплаты / возврата. Для положительного результата нужны содержательные упоминания способа оплаты или условий возврата. Контакты не повторяются при совпадении на нескольких страницах; ссылки на все страницы-источники сохраняются.

## Проверки разработчика

```bash
python3 -m unittest discover -s tests -v
```

Тесты покрывают SSRF-ввод, DNS и перенаправления, анализ страниц, происхождение доказательств, неполные данные, Instagram, HTTP API, независимый сбор при 401, WHOIS-резерв, архив, поиск и защиту API-ключа. Данные внешних сайтов в тестах заменены контролируемыми примерами. Они не доказывают доступность реальных сайтов.

С установленным браузерным модулем доступен дополнительный тест:

```bash
.venv-browser/bin/python tests/native_browser_smoke.py
```

Он проверяет реальный Chromium на локальном контролируемом сервере: обычный клиент получает 401, браузер загружает HTML, выполняет JavaScript и использует анонимную cookie. Все назначения в этом тесте заменены фиксированным локальным сервером; внешние сайты не используются. Тест также проверяет блокировку внутреннего URL и POST. Успех теста не доказывает доступность DNS Shop.

Проверка HTTPS-туннеля (нужен установленный OpenSSL): `.venv-browser/bin/python tests/native_browser_tls_smoke.py`. Она поднимает собственный TLS-сервер с недоверенным сертификатом и требует, чтобы Chromium отклонил сертификат, сохранив безопасный код ошибки в диагностике. Это отрицательный тест проверки TLS; доверие к сертификатам не отключается.

## Архитектура и ограничения

- `app.py`: HTTP API, ограниченный загрузчик HTML, RDAP, анализ видимого текста; стандартная библиотека Python.
- `static/`: адаптивный интерфейс без сборки, CDN, аналитики и внешних шрифтов.
- `tests/`: автоматические тесты.
- `POST /api/check` с JSON `{"url":"https://shop.example"}` возвращает отчёт. `GET /api/health` проверяет запуск сервера.
- Загружаются главная страница и до трёх связанных страниц контактов / оплаты / возврата, только с того же хоста. Браузерная отрисовка главной страницы — дополнительный режим; антибот-защита, сессии и динамические страницы ограничивают полноту.
- RDAP не поддерживает все зоны / поддомены. Дата регистрации не означает возраст бизнеса или время работы нынешнего владельца.
- Проверка сертификата использует системное доверие TLS. Сертификаты не отключаются. HTTPS — свойство соединения, не оценка продавца.
- Введённые ссылки и отчёты не сохраняются на диск. Внешние сайты, DNS и RDAP-провайдер всё равно получают запросы; не вставляйте секретные ссылки и токены. Ответ API и страница не кешируются.

## Сеть и безопасность

Разрешены только HTTP/HTTPS, публичные доменные имена и стандартные порты. Каждое перенаправление проверяется заново, все DNS-адреса должны быть публичными. Прямое соединение закрепляется за проверенным IP с TLS-проверкой исходного имени. Ограничены размер загрузки, число перенаправлений, число страниц и параллельных проверок. HTML внешнего сайта не вставляется в интерфейс: текст отображается через `textContent`.

Приложение сохраняет стандартные настройки HTTP/HTTPS-прокси и доверенных CA. **При использовании прокси сам доверенный прокси также должен запрещать доступ к внутренним адресам и защищать от DNS rebinding:** разрешение имени и транспорт тогда делегируются ему. Не выставляйте прототип в Интернет с произвольным прокси без такой защиты.

В управляемой облачной среде для реальных проверок нужно разрешить домены магазинов, их необходимые перенаправления, `rdap.org`, конечные RDAP-серверы, `web.archive.org` и при включённом поиске `api.search.brave.com`. `403` сетевого прокси — ограничение среды, не свидетельство риска магазина. Не обходите политику сети и не отключайте TLS.

Сервер по умолчанию слушает только loopback. Это сервер разработки, не готовый публичный SaaS. До публичного размещения нужны production-сервер, TLS на входе, фильтрация исходящего трафика, ограничения частоты/ресурсов, общий deadline запросов, защита от злоупотреблений и отдельная проверка безопасности. Не открывайте этот сервер напрямую в Интернет.
