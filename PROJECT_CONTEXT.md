# StoreLens: контекст для продолжения в Codex

Обновлено: 29 октября 2026 года. Состояние приложения при передаче: **0.5.1**,
коммит кода `d16e809`. Этот документ переносит решения из предыдущей переписки.
Он не заменяет проверку актуального кода, рабочего дерева и внешних источников.

## Цель продукта

Веб-сервис «проверь, прежде чем платить»: человек вставляет ссылку на незнакомый
интернет-магазин и получает готовый понятный результат с источниками. Пользователю
не нужно самостоятельно собирать сведения, заполнять анкету или переписываться с ИИ.
Будущие сценарии — Instagram-магазины и проверка поставщиков для компаний.
Ориентир по пользовательскому сценарию — Fraudly; его внутренний алгоритм неизвестен.

В первую очередь важна читаемость: наверху крупная оценка из 100 и короткий вывод,
затем главные причины со ссылками, ниже раскрываемые подробности. Пользователь хочет
понимать, стоит ли доверять магазину. При этом число должно следовать из доступных
данных: нельзя подставлять привлекательный балл или обещать достоверный вердикт при
неполной проверке. Отсутствие данных нужно отличать от обнаруженного риска.

Сбор данных должен быть автоматическим. ИИ в будущем сопоставляет собранные факты
и объясняет противоречия; технические сведения проверяются обычными инструментами.
Сейчас генеративный ИИ в приложении **не подключён**.

## Что работает по коду

- Python HTTP-сервер без обязательных внешних библиотек; интерфейс HTML/CSS/JS
  без сборки. `POST /api/check` принимает JSON с `url`, `GET /api/health` сообщает
  версию и готовность браузера.
- Проверка URL, публичных DNS-адресов, перенаправлений; ограничение размеров,
  количества страниц и времени. Проверка TLS не отключается.
- Чтение главной и до трёх связанных страниц того же хоста: контакты, заявленные
  реквизиты, содержательные условия оплаты и возврата. Повторы контактов удаляются.
  Пункт меню «Оплата» сам по себе не считается условиями оплаты.
- RDAP и резервный WHOIS для доменов второго уровня .ru / .рф; WHOIS не используется
  при настроенном HTTP-прокси. Для составных зон вроде .com.ru этот резерв не реализован.
- Internet Archive CDX: метаданные сохранённой главной страницы, не доказательство
  репутации или исполнения заказов.
- Brave Search API: адаптер есть, ключ берётся из `STORELENS_SEARCH_KEY`.
  Выполняется один поисковый запрос на проверку, передаётся домен, а не полный URL.
  Внешние ссылки и фрагменты помечаются как непроверенные; они не дают баллы репутации.
- Независимые источники проверяются и при недоступной главной странице. Доступные
  результаты сохраняются в частичном отчёте.
- Необязательный настоящий Chromium через отдельный процесс и проверяющий прокси.
  Свежая анонимная сессия, без Safari-cookies и входа в аккаунты. Поддерживается одна
  попытка после обычного HTTP 401 без `WWW-Authenticate`; явная авторизация, CAPTCHA
  и другие ограничения не обходятся. Не отключать sandbox/TLS ради доступа к магазину.
- Верхний блок результата показывает причины ограничений обычного загрузчика и
  браузера отдельно. «Chromium проверен» означает успешный запуск программы, а не
  успешную загрузку конкретного магазина.
- Сохранение PDF использует печать браузера. Ссылки и отчёты не сохраняются на диск.

## Что НЕ реализовано

- Анализ Instagram-профилей: сейчас явное сообщение о неподдерживаемом сценарии.
  Возраст instagram.com нельзя использовать как возраст продавца. Поддержка профилей
  остаётся целью, но её доступность и источники ещё нужно исследовать.
- Проверка принадлежности реквизитов продавцу по реестрам.
- Чтение, сопоставление и подтверждение независимых отзывов и жалоб.
- Интеграция баз фишинга и вредоносных сайтов.
- ИИ-объяснение по собранным доказательствам.
- Сравнение фотографий, полноценный анализ цен и переписки.
- Публичный production-сервис, учётные записи, оплата и тарифы StoreLens.

Методика `evidence-0.1` — предварительный индекс подтверждений, **не вероятность
безопасности** и не обученная модель мошенничества. Сейчас максимум **40/100**:

| Заявленные реквизиты | 5 |

Если нет загруженных страниц и сведений о продавце, показывается **—/100**.
Не выдавать 0/100 за отказ источника и не заменять пропуск произвольным числом.
После подключения независимых данных методику предстоит обосновать и проверить.

## Главная нерешённая проблема: DNS Shop

На Mac пользователя `https://dns-shop.ru` возвращал **HTTP 401** обычному клиенту
и настоящему Chromium даже после успешной установки браузера. Последний отчёт
прямо показывал: «Браузер тоже получил отказ HTTP 401».

При этом удавалось получить дату регистрации домена и запись веб-архива. Этого
недостаточно для числовой оценки продавца. Точная причина отказа не установлена:
не объявлять её доказанной антибот-защитой, проблемой сертификата или отсутствием
Playwright. Не обещать, что переустановка браузера или ключ Brave устранят 401.

Контролируемый тест, где обычный клиент получает 401, а Chromium — 200, проверяет
механику загрузчика. Он **не подтверждает доступ к реальному DNS Shop**.
При диагностике отделять ответ самого сайта от отказа сетевого прокси.

## Brave: что известно к моменту передачи

Ключ в приложение ещё **не подключён**, успешный запрос Search API с ключом не
подтверждён. Секретов в этом документе нет. Автоматической загрузки `.env` нет.

В отдельной локальной сессии Codex пользователь получил такой результат исследования
официальных страниц 29 октября 2026 года (это переданный отчёт; перед активацией
проверить условия в своём Dashboard): Search — $5 за 1000 запросов, ежемесячный
кредит $5 для плана, примерно 1000 запросов Search; возможна активация с предоплатой
$0, но требуется карта. Упомянутые $20 относятся к сумме кредитов разных продуктов,
а не обязательной подписке Search. Автопополнение для бесплатного теста не включать.
Условия атрибуции и хранения результатов необходимо проверить перед публикацией.

Официальные источники для повторной проверки:

- https://brave.com/search/api/
- https://api-dashboard.search.brave.com/documentation/pricing
- https://api-dashboard.search.brave.com/documentation/resources/help-feedback
- https://api-dashboard.search.brave.com/documentation/quickstart
- https://brave.com/blog/most-powerful-search-api-for-ai/

Не покупать план автоматически. Наличие подписки ChatGPT или интернета у Codex не
даёт приложению StoreLens ключ Brave. Поиск Codex и поиск нашего веб-сервиса —
разные вещи. Ключ пользователь вводит локально скрытым вводом; агент не запрашивает
его в сообщении и не выводит значение. Переменную нужно передать **процессу сервера**,
а не только временной оболочке агента. Без отдельной настройки она не сохраняется
при открытии нового Терминала. Подробности текущего ввода — в README.

## Как продолжать: ближайшие задачи

1. Прочитать этот документ, README и код; проверить Git-статус и установленную
   версию. Сохранить чужие изменения. Подтвердить запуск и доступные источники
   на Mac; не возвращаться к ZIP и настройкам старой облачной среды.
2. Подготовить подключение Brave. Самостоятельно сделать всё, что не требует
   ключа или покупки. Если ключа нет, дать пользователю одну точную инструкцию
   создания и скрытого ввода, объяснить стоимость по актуальным официальным данным.
   Не блокировать независимые задачи ожиданием ключа и не делать повторные запросы
   к платному API без необходимости.
3. С ключом проверить настоящий поиск и полный путь `POST /api/check`: результаты
   доступны и при 401 магазина; источники кликабельны; ошибки авторизации/лимита не
   превращаются в отрицательную репутацию; ключ не попадает в отчёт и логи.
4. Проверить на пяти магазинах пользователя и DNS, записать краткую сводку:
   доступ к странице, домен, архив, поиск, возможность оценки, конкретный пробел.
   Не давать этим магазинам заранее заданных баллов или обвинений.
5. Следующий этап разработки — содержательная проверка найденных внешних источников:
   принадлежность именно этому продавцу, даты и конкретные утверждения с цитатами.
   Выбрать небольшой проверяемый этап и реализовать его. Учитывать лицензии и
   стоимость провайдеров; не начислять баллы за простое количество ссылок.
6. Затем подключать подходящие реестры/источник угроз, пересматривать обоснованную
   оценку и добавлять ИИ-объяснение по проверенным фактам. Instagram исследовать
   отдельно, явно обозначая ограничения получения данных.

Приоритет: реальная полезность проверки и понятный итог. Не заменять работу с
источниками очередной косметической перестановкой карточек или искусственным баллом.

Магазины для проверки: `galaxyshub.ru`, `galaxypoint.ru`, `kadrum.store`,
`fmart.com.ru`, `tecnotop.ru`. Дополнительно: `dns-shop.ru`, несуществующий домен,
публичная ссылка Instagram и запрещённый ввод `http://127.0.0.1`.

## Команды и карта кода

Команды ниже вводятся в **обычную командную строку Терминала**, не в поле сообщения
Codex. Агент может выполнять их своими инструментами.

```bash
cd ~/StoreLens
git status --short --branch
python3 app.py --version
```

Рекомендуемый запуск с установкой/проверкой браузера:

```bash
bash ./start-mac.command
```

Если зависимости уже готовы:

```bash
.venv-browser/bin/python app.py --browser --port 8001
```

Браузер: `http://127.0.0.1:8001`. Сервер должен продолжать работать, пока пользователь
тестирует. Если агент запускает его своим инструментом, проверить, что процесс не
завершился вместе с командой. Не останавливать чужие процессы на занятом порту.
Для публичного размещения текущий сервер разработки не предназначен.

Тесты, соответствующие изменению:

```bash
python3 -m unittest discover -s tests -v
.venv-browser/bin/python tests/native_browser_smoke.py
.venv-browser/bin/python tests/native_browser_tls_smoke.py
```

Последний прогон до передачи: 59 unittest-тестов прошли в облачной среде. Это
исторический результат, а не новый прогон на Mac. Браузерные smoke-тесты используют
собственные локальные серверы. TLS-тест требует OpenSSL и проверяет отклонение
недоверенного сертификата. Подробности, включая ограничения облачного sandbox,
описаны в README и самих тестах. Для изменения только документации эти тесты не нужны.

| Файл | Назначение |
| --- | --- |
| `app.py` | API, сбор источников, анализ текста, итог, оценка |
| `browser_worker.py` | Отдельный процесс Chromium и безопасная диагностика |
| `browser_proxy.py` | Проверка сетевых назначений браузера, туннели |
| `static/index.html`, `static/app.js`, `static/style.css` | Интерфейс отчёта |
| `start-mac.command` | Запуск через собственную `.venv-browser` |
| `requirements-browser.txt` | Необязательная зависимость Playwright |
| `tests/` | Автоматические проверки и контролируемые браузерные сценарии |
| `README.md` | Подробный запуск, методика и ограничения |
